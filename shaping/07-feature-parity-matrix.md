# 完整功能对齐矩阵

## 状态定义

| 状态 | 含义 |
| --- | --- |
| `READY` | Uni 已有可复用的正式工程能力，后续主要做视觉/验收对齐 |
| `PARTIAL` | Uni 有领域或页面基础，但尚未满足完整目标 |
| `MISSING` | Uni 当前未覆盖，需纳入后续 PRD |
| `STRONGER` | Uni 的实现明显强于 MVP/Web，应保留而不是退回旧做法 |
| `OPEN` | 产品规则未定，不能直接实现 |

## 对齐原则

- “Uni 当前状态”是差距盘点，不是范围裁剪依据。
- MVP 代码与 PRD 中存在、且用户没有明确删除的功能，保留在完整目标中。
- 工程实现优先延续 Uni；用户可见功能与视觉优先向 MVP/Web 对齐。

## 结论

Uni 不是“接近完成、只需要换皮”。它已经搭好了更可靠的骨架，但完整产品在用户侧仍缺一大块，尤其是多成分确认、成分日历、计划总览、成本、AI/笔记/健康资料。正确路线是保留 Uni 的骨架，按本矩阵逐项恢复和重构用户能力。
